# Section SOP: Plagiarism + References Review

This is the last text pass before PDF assembly — the only stage that reads the **whole**
assembled draft at once (every other section was drafted independently, so this is the
first point anything checks them against each other and against the source material as
one document).

## 1. Cross-check every factual claim

Read all 8 drafted sections plus `valuation_inputs.json`, `price_consensus_research.json`,
`recommendation_decision.json`, and the institution's `research_output.md`. For every
number or named fact in the sections, confirm it traces back to one of those files. Flag
(don't silently fix) anything that doesn't — a number that doesn't trace to source is a
more serious problem than a stylistic one and should be called out explicitly, not
quietly patched over.

**`valuation_inputs.json`'s `company_facts`, `ias29_impact_primary_year`, and
`monetary_exposure` blocks are the single authoritative source** for consolidated totals,
per-subsidiary IAS 29 impact figures, and exposure grades — they're the model's own
corrected figures. If any section states one of these facts with a value that doesn't
match those blocks (e.g. it instead matches an earlier or superseded figure that may
still appear somewhere in `research_output.md`), that is a coherence finding — flag it
explicitly, with both the expected (JSON) value and the actual (stated) value, even if
the stated value is individually "sourced" somewhere in `research_output.md`. Being
traceable to *a* file is not sufficient if it contradicts the model's own authoritative
figure for that same fact.

## 2. Check for near-verbatim copying

Sections were drafted independently and may unintentionally repeat the same sentence or
turn of phrase from `research_output.md` or a cited source near-verbatim without
quotation. Flag any passage of more than ~15 consecutive words that matches source text
closely enough that it should either be quoted directly (with attribution) or
rephrased. This is about intellectual honesty toward the source material, not about
external plagiarism-detection tooling this environment doesn't have.

## 3. Check for internal consistency

Since each section was drafted independently, verify they don't contradict each other —
e.g. the Recommendation section's final call should match what the Investment Thesis
section previewed; the Bulls/Bears tension should be reflected consistently in the Risks
section. Flag contradictions rather than silently picking one version.

## 4. Assemble the References section

Collect every source cited across all 8 sections and the JSON files (the institution's
annual report/Form 20-F filings, consensus/proxy source, any URLs or named research) into
one deduplicated list, in the order first cited. Format as a simple markdown list:
`- [n] Description — URL or citation, accessed date if known`.

## 5. Output — two separate files, never mixed

This stage writes **two files**, at the exact paths you're given. Never put findings
content inside the client-facing document, and never put the document's prose inside the
findings file — a later pipeline stage renders the document verbatim into the client PDF,
so anything written there is something an investor will read.

**File 1 — the assembled document** (path given to you as the "document path"):
concatenate all 8 sections in their given order, then append your assembled
`## Sources & References` section, then a final `## Disclaimer` section with this exact
boilerplate text:

> This report is generated by an automated financial-model-and-research pipeline for
> educational and research purposes. It is not investment advice. Valuation figures
> depend on modeling assumptions disclosed throughout this report and in the underlying
> model's `research_output.md`; all data should be independently verified before use in
> any investment decision.

This file contains **only** client-facing report content — no QA commentary, no review
notes, no meta-discussion of what you checked. If you found no issues in steps 1-3, this
is the entire content of your job for this stage's document output.

**File 2 — findings** (path given to you as the "findings path"): a JSON array, one
object per unresolved issue found in steps 1-3 (a claim that doesn't trace to source or
contradicts `company_facts`, a near-verbatim passage, or a cross-section contradiction).
Empty array `[]` if none. Each object:

```json
{
  "severity": "high|medium|low",
  "section": "e.g. 01_investment_thesis",
  "description": "Plain-language description of the issue.",
  "expected_value": "The correct value/fact and where it comes from (e.g. company_facts.total_equity = 32107.51), or null if not a value mismatch.",
  "actual_value": "What the section currently states, or null if not a value mismatch."
}
```

Do not silently rewrite section content to fix an issue — flag it in the findings file
instead; a later stage (the coherence gate) is responsible for applying corrections.
